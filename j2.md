# J2 Project Overview

## Introduction

J2 is a system that combines a minimalist programming language called "Edict" (for "executable dictionary") with a C reflection/FFI (Foreign Function Interface) system. It allows developers to easily import shared libraries and use the datatypes, variables, and functions within them directly, without needing to write any "glue" code.

The project enables runtime reflection capabilities for C programs, allowing them to expose dynamic access to their own internals at runtime. This creates a powerful bridge between the static world of compiled C code and the dynamic world of interpreted languages.

## Core Components

### 1. Listree Data Structure

The foundation of J2 is the "Listree" (List Tree) data structure, which serves as the universal container for all data in the system:

- A Listree Value contains zero or one buffer(s) of arbitrary data, and zero or more labeled references to other Listree Values
- This recursive structure allows for hierarchical organization of data
- All system state, including the data stack and dictionary, is maintained within Listree Values

### 2. Reflection System

The reflection system allows J2 to understand and interact with C libraries:

- Uses DWARF debugging information to import C type, function, and variable definitions
- Provides runtime type information for C data structures
- Enables dynamic binding with C libraries without writing wrappers or glue code
- Implemented primarily in `reflect.cc` and `reflect.h`

### 3. Virtual Machine

The VM executes bytecode that operates on the Listree data structure:

- Simple, stackless VM with a nearly condition-free inner loop
- Bytecode operations for manipulating the data stack and dictionary
- Support for exceptions and function calls
- Implemented in `vm.cc` and `vm.h`

### 4. Edict Language

Edict is a minimalist programming language with the following characteristics:

- Stack-based: operations pop arguments from and push results to a data stack
- Dictionary-based: named values are stored in a hierarchical dictionary
- Evaluation-based: code is data until explicitly evaluated with the `!` operator
- Reflection-aware: seamlessly interacts with imported C libraries
- Compiled into bytecode by the JIT compiler in `compile.cc`

## Key Features

### C Library Integration

J2 can import C libraries and directly use their:
- Types (structs, enums, etc.)
- Global variables
- Functions

This is done by analyzing the DWARF debugging information in the shared library, without requiring any special preparation of the library.

### Evaluation Model

Edict has a unique evaluation model:
- It doesn't have traditional functions
- Instead, it has an evaluation operator (`!`) that can be applied to values
- This allows for flexible code composition and execution

### Concurrency Support

The bootstrap.edict file shows support for:
- Asynchronous execution via `vm_eval`, `vm_async`
- Continuations
- Thread management with `async` and `await` operations

## Implementation Details

### Memory Management

The Listree structure includes reference counting for memory management:
- `LTV_init`, `LTV_renew`, and `LTV_free` handle Listree Value lifecycle
- Various flags (LT_DUP, LT_OWN, etc.) control memory ownership

### FFI (Foreign Function Interface)

The FFI system allows calling C functions from Edict:
- Uses libffi for dynamic function calls
- Handles marshaling of arguments and return values
- Supports type coercion between Edict values and C types

### Compilation

The compilation system converts Edict code to bytecode:
- `jit_edict` compiles Edict source code to VM bytecode
- Support for other formats like XML is also present
- The bytecode is then executed by the VM

## Usage Example

A simple example of using J2 to interact with a C library:

```
// Create a shared library with a C function
// inc.c:
typedef struct mystruct { int i; float f; } mystruct;
extern mystruct increment(mystruct x) { x.i+=1; x.f+=1; return x; }

// Compile to shared library:
gcc --shared -g inc.c -o inc.so

// In Edict:
loadlib([inc.so]) @mylib              // Import the library
mylib<mystruct! <2@i 4@f> @x          // Create a mystruct instance
increment(x)>/                        // Call the C function
stack!                                // Display the result
```

## Project Structure

- `listree.cc/h`: Core data structure implementation
- `reflect.cc/h`: C reflection system using DWARF information
- `vm.cc/h`: Virtual machine implementation
- `compile.cc/h`: Bytecode compilation system
- `cll.cc/h`: Circular linked list implementation used by Listree
- `util.cc/h`: Utility functions
- `extensions.cc/h`: Extended functionality
- `bootstrap.edict`: Initial Edict code loaded at startup

The diagram above illustrates the hierarchical organization of the J2 system. At the core are the fundamental data structures, primarily the Listree, which serves as the foundation for the dictionary, data stack, and code stack. The Edict language parser/compiler translates source code into bytecode, which is then executed by the virtual machine.

The reflection system processes DWARF debugging information from shared libraries to build a type database, which enables the FFI system to make calls to C functions. The bootstrap engine initializes the system and provides the basic Edict functions needed for operation.

All components interact through well-defined interfaces, with the Listree serving as the common data representation format throughout the system. This architecture allows J2 to seamlessly bridge the gap between the static world of compiled C code and the dynamic world of interpreted languages.
